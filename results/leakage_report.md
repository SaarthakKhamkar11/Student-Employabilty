**Reading.** No feature uses information that only exists after the fact: every one is computed from the profile and the posting at request time, and there is no employment outcome anywhere in the data (outcome-like columns found: none), so outcome leakage is impossible here. But the TRAINING target is the weak labels, and the features marked above read the same inputs the weak labels are generated from. A model trained on weak labels can therefore learn the labelling rule instead of fit. The gap between the weak-label AUC and the human-label AUC of those features is the measured size of that shortcut. It is why every trained model's top SHAP feature is `branch_match` or `career_interest_alignment` (Phases 8 and 11), and why model selection and every RQ answer use human labels only.
- Unsupervised, label-free use of evaluation students: the similarity percentiles are calibrated over all students x all jobs (app/matching/calibration.py), test students included. No label is involved, so this is transductive, not target leakage.
