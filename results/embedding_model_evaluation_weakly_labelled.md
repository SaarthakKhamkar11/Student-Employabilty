## Not run

- **E. Custom / domain-adapted: Not feasible — insufficient labeled data.** Fine-tuning a domain model needs thousands of labelled student-job pairs; the project has 286 students and no labelled training pairs yet (the human benchmark is for evaluation only).
- **F. Hybrid (semantic + structured features):** Spec §6: a hybrid model is not an embedding model. It combines the selected embedding's similarity with structured features, so it is compared with the matching models, not here. This is a separate architecture, not a gap in this comparison.

## Limitations

- The job corpus is synthetic and templated: 376 distinct role texts. Results describe this data, not real job boards.
- Quality is measured on the validation split only; test is held back for Phase 14, so these numbers are the basis for selection, not a final unbiased estimate.
- Weak labels only encode "job in the student's stated field" from hand-written rules (config/weak_label_rules.yaml); they ignore the student's actual skills, and they can't separate a strong match from a moderate one. They test the framework and give a first signal, not a selection.
- Costs are from one developer laptop with other services running.
